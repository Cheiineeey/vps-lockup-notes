事故补充 · VPS Security Notes

《锁门》之外：
我们从事故里补出的 8 条规则

这不是另一份 VPS 入门教程，也不重复端口、SSH、补丁和备份。这里只记录我们在网站被完整复制、内部服务意外暴露公网，以及后续安全复盘中真正踩出来的坑。

阅读顺序：请先看铜铜和 Monday 写的 《锁门》。这篇不是对它的改写，只记录我们后来在自己的服务器上遇到的事故，以及从中补出来的规则。

为什么会有这份补充

我们曾经以为“网页能正常打开、主要 API 已经鉴权、服务前面有防火墙”就已经足够。后来，一个公开站被完整复制；一个原本只供内部使用的服务被发现监听在公网；再后来，主 API 虽然锁住了，同一批私人数据却还能从另一条入口被匿名读取。

这些不是八个孤立的配置错误，而是八条应该长期成立的系统规则。

01

默认前端一定会被完整复制

浏览器能够显示的 HTML、脚本、图片和文字，就已经完整交到了访问者手里。禁用右键、代码混淆和禁止搜索引擎收录，都不能让公开页面变成私人页面。

规则：公开作品与私人生活从构建阶段就分开；不愿被复制的内容，只能放在服务端鉴权之后。

02

按“入口”审计，不按“服务”审计

同一个功能可能同时经过不同域名、直接 IP、反向代理前缀和上游端口。锁住主 API，并不等于同一批数据没有从平行入口流出去。

规则：为每个公网入口单独列账，在共用闸门默认拒绝，只显式放行最小范围；再从服务器之外逐个进行匿名请求。

03

鉴权级别由最终副作用决定

GET 不保证只读。一个叫“状态”或“事件”的接口，背后仍可能写文件、调用付费模型、发送通知，甚至改变聊天记录。只按照请求方法划分风险，会漏掉最危险的入口。

规则：沿着调用链看到最后；凡是会写入、花钱、通知他人或调用内部能力的请求，都按高危写操作保护。

04

别让公网入口借服务器身份办事

一个公开入口即使不直接泄露密钥，也可能使用服务器自己的高权限凭据，替匿名请求访问内部服务。这时门锁着，门房却在替陌生人开门。反向代理还会让公网请求在应用里看起来同样来自 127.0.0.1；这个地址只能证明上一跳是代理，不能证明调用者就在本机。

规则：只有真正限制在本机、并且不会被公网反代到的通道才能免鉴权；不能只凭 loopback 来源放行。公网入口必须先确认调用者身份，再使用最小权限的独立凭据。

05

失败请求会响，敏感的成功也要响

401 和 403 只能说明有人撞到了锁。真正需要立刻处理的，往往是陌生来源从私人接口拿到了 200。只监控失败，会把已经进门的人当成一切正常。

规则：同时监控敏感接口的异常 2xx、新来源成功、新监听端口，以及短时间内突然增加的高权限操作。

06

密钥暴露后的动作是轮换，不是删除

密钥一旦进入公开网页、URL、Git 或访问日志，就可能继续存在于浏览器历史、缓存、旧提交和备份里。把当前文件中的那一行删掉，并不能让已经出现过的值失效；后端已经改用安全代理，也不代表某个旧页面里没有遗留原值。

规则：按“已经泄露”处理，先撤销并轮换，再扫描整棵发布目录和历史残留；不同客户端使用可单独撤销、权限不同的令牌。

07

相信正在运行的事实，不相信旧笔记

服务可能换过进程管理器，端口可能被另一份旧进程占用，配置备份也可能因为留在自动加载目录而重新生效。文档写着什么，并不等于线上此刻运行什么。

规则：变更前核对真实进程、父进程、监听地址和实际加载的配置；备份永远放在活目录之外。

08

安全检查必须跟着系统一起变化

一次通过的端口扫描，只能证明当时。系统更新、重启、迁移运行方式、增加反向代理或新增接口，都可能悄悄改变边界。上锁前还要先盘点真实调用方：App、网页、快捷指令和服务器内部任务，可能正在共用同一条入口。

规则：每次边界变更后，既验证陌生人确实被拒绝，也验证合法客户端仍然成功；按 UA 放行和限流只能是临时兼容，必须写清删除条件。

可以直接抄走的增补清单

基础锁门完成以后，再确认下面八件事。

  • 整棵公开发布目录即使被完整复制，也不会带走私人内容、秘密或高价值能力。
  • 域名、直接 IP、每个反代前缀和上游端口都做过外部匿名测试，并由共用闸门默认拒绝。
  • 所有会写入、花钱、通知或调用内部能力的接口都按高危操作鉴权。
  • 公网入口不能无条件借用服务器的高权限内部身份，也不能把反代后的 loopback 当作调用者身份。
  • 告警覆盖陌生来源的敏感 2xx，而不只覆盖 401 和 403。
  • 进入过网页、URL、Git 或日志的密钥已经撤销并轮换，整棵发布目录也重新扫过。
  • 进程、监听与加载配置以现场为准，备份文件不在活目录里。
  • 每次部署、重启和边界变化后，都同时验证匿名者被拒绝、合法客户端成功；临时兼容有明确删除条件。

这份补充刻意隐去了真实域名、接口路径、IP、端口和令牌形式。分享事故，是为了让规则可以复用，不是为了把私人系统画成一张攻击地图。
